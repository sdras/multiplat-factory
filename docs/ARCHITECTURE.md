# Architecture

This is the design document the factory was built from. It stays the design document, with corrections in place where the code settled differently. The section right below lists the material differences; the sections after it carry the corrected detail. When this document and the code disagree, the code is right and this document has a bug.

## Where the implementation differs from this plan

Each item was checked against the code in the paths named.

- **Every LLM call is an Agent SDK worker.** `runWorker` (`packages/analyzer/src/worker.ts`) wraps `runAgent` (`packages/llm/src/agent.ts`) for the spec, behaviors, plan, core, generate, build-fix, test-fix, critique, and fix stages. The Messages backend (`structuredCall` in `packages/llm/src/messages.ts`) exists and `detectBackend` and the doctor still report `messages` versus `agent-sdk`, but no stage calls it. The plan and the critic are workers with read-only tools, not `messages.parse` calls.
- **The report stage is deterministic.** `packages/orchestrator/src/stages/report.ts` writes `PORT.md` per target, `report.json`, and the one-line run summary with no LLM.
- **The flow compilers live in the adapters, and the web side is an executor, not generated spec files.** `packages/adapters/src/target/maestro.ts` compiles one behavior to Maestro YAML; `packages/adapters/src/target/web/executor.ts` runs BehaviorSpec steps directly in Playwright. The planned `analyzer/src/flows/compile.ts` does not exist. The web target writes each behavior to `flows/<id>.json` and the executor runs it against `vite preview`; the observe stage runs the same executor against the source app.
- **The BehaviorSpec step vocabulary grew** to `navigate`, `openRoute`, `tap`, `doubleTap`, `longPress`, `type`, `select`, `swipe`, `expectVisible`, `expectHidden`, `expectText`, `expectCount`, `restart`, `seed`, `wait`, and `custom` (`packages/core/src/schemas/behaviorspec.ts`). Section 5 lists what each compiles to and where each stops.
- **Source observation covers iOS and Android sources.** `observeMobile` on `ios-xcode` and `android-gradle` builds the source app for the simulator or emulator; the observe stage walks the behaviors with Maestro flows compiled in `navigation: 'none'` mode and runs the source's own test suite (`existingTests`) as a `source` test result. Golden vectors are not recorded by generated SwiftPM or JVM harnesses; the core workers may run the source's interpreter instead (`logicRunnerAllow` in `packages/adapters/src/core/embed.ts`).
- **Source adapters are grouped by platform**, not one file per framework: `packages/adapters/src/source/{web,mobile,cross}.ts`. `ios-xcode` covers `.xcodeproj`, `.xcworkspace`, and a checked-in XcodeGen `project.yml`; there is no separate `ios-xcodeproj` adapter.
- **Ambiguous detection does not pause.** `ingest` logs the top candidates and takes the best score; only an unrecognized or unsupported source fails the stage (`unsupported-source`). The planned `waiting_human` on ties is not implemented.
- **Fix loops and termination.** Build-fix (3 rounds) and test-fix (2 rounds) run inside `build:<t>` and `test:<t>` by resuming the generation session. The critic allows 2 rounds and escalates when the blocking set does not shrink, when its confidence is below 0.5, or when the round budget is spent. A successful `fix:<t>` resets `build`, `test`, `critique`, `fix`, and `report` for that target; `fix` has `maxAttempts: 5`. There is no 90-minute wall clock and no no-progress hash detector. The run pauses when its budget is reached; there is no top-up control (the `topup` control action exists only in the event schema).
- **Worker budgets and turn caps** differ from the original table; section 3.2 now shows the implemented values, including the $3 floor per worker call and $5 for resumed sessions.
- **Human checkpoints are two:** plan approval (`approve` or `reject`) and critic escalation (`accept` or `reject`). Any answer other than `reject` re-queues the stage with the choice attached; `reject` cancels the run. The `beforeFixLoop` option is declared in `RunOptions` and set by `--yes`, but no stage reads it.
- **Dashboard pages** are `/`, `/runs/new`, `/runs/:id`, `/runs/:id/spec`, `/runs/:id/plan`, `/runs/:id/tests`, `/runs/:id/critic`, `/runs/:id/core`, and `/doctor`. There is no per-stage page, screens page, artifacts page, or settings page; the transcript is on the run page and the screenshots are on the tests page. State lives in composables over `@mpf/core/reducer`; the Pinia module is installed but no store is defined.
- **Devices and test hooks.** Seeding and routing use `mpf_seed` and `mpf_route` (iOS launch arguments), `mpf_seed` (Android intent extra), and `?mpf_seed=` (web). There are no `MPF_UITEST` or `MPF_SEED` variables, no locale or timezone pinning, no simulator erase between targets, and no pixel diffs (`pngjs` and `pixelmatch` are in the catalog and unused). Android deep links are `mpf://<applicationId>/<screenId>`; iOS flows relaunch with `mpf_route` instead of opening URLs.
- **Artifacts are not zipped.** Build products are recorded in place; a directory such as an iOS `.app` is recorded as `inode/directory` with its total size and no hash.
- **Versions.** Chicory is 1.7.5, not 1.4.0. Grammars come from `tree-sitter-wasm` 2.x on `web-tree-sitter` 0.27, not `tree-sitter-wasms`. The workspace runs pnpm 12 (`packageManager`), Node >= 22.13, `.nvmrc` 24.
- **Critic rubrics are constants** in `packages/critic/src/rubrics.ts` (fidelity, idiomatic per target, tests, parity docs, build, privacy), not markdown files, and there is one backend: the Agent SDK worker.
- **Fixtures.** `fixtures/manifest.json` pins ten public repos and lists five in-house fixtures: `web-vanilla-counter`, `web-vanilla-cart`, `ios-uikit-notes`, `ios-objc-notes`, `android-views-java-notes`. There is no `web-svelte-notes`, and no personal project is pinned.
- **Verification.** CI runs the fake pipeline with `--fake --yes`; there is no `--fake-llm`, no `--fixture-mode`, no `MPF_RECORD` replay (the `AgentRecorder` only appends JSONL), no nightly real-LLM job, and no "Run self-test" button. CI does have jobs the plan did not list: the four web scaffold flavors with a Playwright flow, the in-house mobile fixtures building and passing their own tests, and the public fixture matrix detection check.
- **Doctor checks** are node, git, pm, llm, xcode, java, android, gradle, rust, and maestro. There is no Playwright Chromium check; the observe stage degrades to "unverified" without the browser.
- **Publishing.** `pnpm tsx scripts/release.ts` builds and packs `multiplat-factory` (a tsup bundle plus the static dashboard copied by `apps/cli/scripts/bundle-dashboard.mjs`); `--publish` runs `pnpm publish`. There are no `release` or `test:e2e` root scripts, and the package is not on npm yet.
- **File placement.** The worker spawner is `packages/llm/src/agent.ts` plus `packages/analyzer/src/worker.ts`, not `packages/orchestrator/src/worker.ts`; the orchestrator is split into `graph.ts`, `machine.ts`, and `runner.ts`.

## Context

**multiplat-factory** is a general-purpose product: give it an app built for one platform (web, iOS, or Android), pick the other platforms you want, and it produces fully functional builds for them. The factory is itself an app: a dashboard for communicating with the process and observing it. Inside are a deterministic orchestrator, LLM workers that do the porting, a verification harness, a critic LLM with independent context, and testing infrastructure that proves the port still behaves like the original. WASM is used where it genuinely applies: a shared logic core that runs on all three platforms, tree-sitter grammars for uniform source parsing, and a core playground in the dashboard.

The repository was empty when this was written.

### Product principles

- **For anyone, not for one person.** Accepts any reasonable app: web in React, Vue, Svelte, Angular, Solid, vanilla, SPA or SSR; iOS in SwiftUI or UIKit, Swift or Objective-C, Xcode or SwiftPM; Android in Compose or XML Views, Kotlin or Java, single or multi-module. Cross-platform sources (Flutter, React Native, Capacitor) are recognized and refused with a message. All platform knowledge lives in pluggable source and target adapters behind a framework-neutral AppSpec and BehaviorSpec.
- **No machine-specific code.** Toolchains are discovered through `DEVELOPER_DIR` or `xcode-select`, `xcrun`, `JAVA_HOME`, `ANDROID_HOME`, PATH, with overrides in `~/.mpf/config.json` or `mpf.config.ts`. `mpf doctor` reports gaps with install hints per package manager; `mpf setup` asks before installing. Missing toolchains skip a target with a plain reason (iOS needs macOS + Xcode; web and Android also run on Linux).
- **Bring your own credentials and budget.** `ANTHROPIC_API_KEY` or Claude Code login. Models configurable with defaults (`claude-opus-5` for generation and critic, `claude-sonnet-5` for cheap sub-tasks). Per-run budget cap with a visible meter.
- **Installable and local-first.** `npm i -g multiplat-factory` or `npx`, run data under `~/.mpf/` (honors `$MPF_HOME`, then `$XDG_DATA_HOME/mpf`), with interfaces (`RunStore`, `AgentFn`, `StageRunnerRegistry`, `RunEventBus`) that leave a clean seam for a hosted or CI mode later (`docs/HOSTED-SEAM.md`).
- **Nobody's own projects shape the product.** Fixtures are pinned by git URL + commit like any other fixture, or written in-house under `fixtures/inhouse`, and are never the basis for templates, prompts, or defaults.

### Verified facts the design relies on

- Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`): `query({prompt, options})` yields SDK messages. The options the factory passes are `cwd`, `additionalDirectories`, `model`, `effort`, `maxTurns`, `maxBudgetUsd`, `disallowedTools`, `permissionMode: 'default'`, `canUseTool`, `settingSources: []`, `persistSession`, `enableFileCheckpointing`, `resume`, `abortController`, `env`, `systemPrompt`, and `outputFormat` (draft-7 JSON Schema without a `$schema` key). The result carries `total_cost_usd` and `session_id`. `allowedTools` is never passed: bare entries auto-approve a tool before `canUseTool` runs.
- Messages API (`@anthropic-ai/sdk`): `client.messages.parse` + `zodOutputFormat` is wrapped by `structuredCall` in `@mpf/llm`; no stage uses it today.
- iOS forbids JIT and JavaScriptCore's `JSContext` has no WebAssembly. **WasmKit 0.4.0** (pure Swift interpreter, SwiftPM, needs swift-tools 6.3 / Xcode 26.3+, raises the deployment target to iOS 18) is the iOS host. **Chicory 1.7.5** (pure Java, `com.dylibso.chicory:runtime`, API 28+) is the Android host.
- **Maestro** (Homebrew formula `mobile-dev-inc/tap/maestro`) drives simulators and emulators from YAML and supports SwiftUI, UIKit, Compose, Views. **Playwright** for web. **XcodeGen** generates `.xcodeproj` from `project.yml`.
- `tree-sitter-wasm` 2.x ships grammars as `out/<lang>/tree-sitter-<lang>.wasm` and loads on `web-tree-sitter` 0.27; the inventory maps javascript, typescript, tsx, swift, kotlin, java, and objc to it, and parses Vue and Svelte files with the typescript grammar. `tree-sitter-wasms` 0.1.x uses the legacy `dylink` section and only loads on web-tree-sitter 0.22.
- `node:sqlite` is unflagged from Node 22.13 (`engines.node >= 22.13`, `.nvmrc` 24).
- Android `sdkmanager` offers `emulator` and `system-images;android-36;google_apis;arm64-v8a`. macOS has no `timeout` binary; scripts use execa timeouts.
- Gradle 8.14 / AGP 8.13 run on JDK 17-24 only; the doctor reports out-of-range JDKs and the harness prefers `openjdk@21`.

### Environment at planning time (first-run notes only)

Present on the machine the plan was written on: Node 22.11, pnpm 10.15, Go, Python, git, gh, Homebrew, Claude Code (authenticated, no `ANTHROPIC_API_KEY`), Xcode 26.6 with iOS 26.5 and 18.1 simulators, Android command-line tools with build-tools 35/36 and platform-tools, OpenJDK 24 (keg-only), Gradle. Needed fixing: `xcode-select` pointed at CommandLineTools; `JAVA_HOME`, `ANDROID_HOME` unset; no emulator or system image. Missing: Rust, Maestro, XcodeGen, Playwright browsers. `mpf doctor` reports all of this on any machine now.

### Local fixtures considered at planning time

A hand-made SwiftUI to Compose port (README with architecture map, wire-format pins, intentional parity quirks, known deviations, and a serialization parity test) served as the model for the generalized `PORT.md`, and three small React apps were candidates for pinning. None of them is in `fixtures/manifest.json`; the in-house fixtures under `fixtures/inhouse` and the public matrix took their place.

Stage kinds: `ingest`, `inventory`, `spec`, `behaviors`, `observe`, `plan`, `core.extract`, `core.vectors`, `core.build`, `generate:<t>`, `build:<t>`, `test:<t>`, `critique:<t>`, `fix:<t>`, `report`.

Stage state machine (`packages/orchestrator/src/machine.ts`, pure transition functions, table-tested):

```
pending --(deps met)--> queued --> running --> succeeded                                               [terminal]
                                   |--> failed --(attempt < max)--> queued
                                   |--> failed --(attempt >= max, or the outcome is not retryable)--> blocked   [terminal]
                                   |--> waiting_human --(any answer but reject)--> queued, with the choice attached
                                   |--> waiting_human --(reject)--> cancelled, along with the whole run
                                   |--> paused --(resume)--> queued
pending --(core not warranted | no adapter | toolchain absent)--> skipped                                [terminal]
pending --(a dependency ended blocked or cancelled)--> skipped "unreachable: ..."                          [terminal]
any non-terminal --(run cancel)--> cancelled                                                             [terminal]
succeeded | failed | blocked | paused | waiting_human --(rerun, or a fix-loop reset)--> pending/queued
```

A dependency is satisfied when it succeeded or was skipped on purpose; `report` has soft dependencies and runs once every `fix:<t>` has ended, however it ended. Run status derives from stages: explicit cancel wins; any `waiting_human` stage makes the run `waiting_human`; explicit pause wins next; otherwise all terminal with nothing blocked and every target delivered -> `succeeded`; a blocked untargeted stage or every target undelivered -> `failed`; some targets undelivered -> `partial`.

## 3. Pipeline

Principles: the orchestrator is deterministic TypeScript, never an LLM. LLM stages emit structured artifacts validated by zod. "Green scaffold" rule: every target project builds before an LLM edits it. Workers never see each other's transcripts, only artifacts.

### 3.1 Stages

| Stage          | Driver                                                                                                                                                          | Inputs -> Outputs                                                                                                                                                                                                                                                                                                                               |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ingest`       | deterministic                                                                                                                                                   | locator -> `runDir/source/` (git clone at commit or copy excluding build dirs); adapter registry scores detection, best wins, a `detection` artifact records all candidates; an unrecognized or unsupported source fails the stage with `unsupported-source`; an ambiguous detection (two scores within 0.05) is logged and the best score wins |
| `inventory`    | deterministic                                                                                                                                                   | tree-sitter symbol/import inventory, files by role, adapter hints, and the test hooks the source already exposes (`hints.testHooks`)                                                                                                                                                                                                            |
| `spec`         | worker, read-only tools                                                                                                                                         | inventory + hints -> `AppSpec` (every element gets a `testId`); one repair round when element test ids match none of the source's hooks                                                                                                                                                                                                         |

The per-call cap is `max(min(floor, remaining), min(remaining, budgetUsd * share))` with a floor of $3, or $5 for a resumed session whose long transcript makes every turn cost more. A resumed session's result reports the whole session's spend; `runWorker` keeps `sessions.json` in the run directory and charges only the increment. Cost is charged to the stage and the run the moment a worker returns (`ctx.chargeCost`).

Common options (`packages/llm/src/agent.ts`): `permissionMode: 'default'` with a `canUseTool` callback over the pure policy in `packages/llm/src/permissions.ts` (writes only under cwd; reads under cwd and the extra read dirs; Bash must match the allowlist for every command in a `;`/`&&`/`||` sequence or `for` loop, may not use `..` or `~` paths, and may not reference absolute paths outside the allowed roots; `cd <inside> && ...` is judged on the command after the `cd`); `disallowedTools` denies WebFetch, WebSearch, Workflow, Agent, and Task; `settingSources: []` (never inherit the user's `~/.claude`); `persistSession: true`; `enableFileCheckpointing: true`; `abortController` wired to pause and cancel; `maxBudgetUsd` from the table; `env` carries `MPF_RUN_ID`, `MPF_STAGE_ID`, and the resolved toolchain variables. Tool events for the transcript come from the SDK message stream, not hooks. Operator instructions are queued per stage and handed to the next worker that stage starts (`ctx.takeInstructions()`); nothing is injected mid-session.

### 3.3 Retry, fix loop, termination

- Build failure: up to 3 build-fix rounds inside `build:<t>`, each resuming the generation session with the diagnostics and the log tail; a failed build with no parseable diagnostics gets a synthetic error from the log tail.
- Test failure: up to 2 test-fix rounds inside `test:<t>`; a failing must-behavior flow is rerun once first, and a case that passes on the retry is `flaky` and never triggers a fix. Unit failures, a failed launch check, and failing must-behaviors are the only blocking failures; `should` behaviors never block.
- Critic: max 2 rounds per target. The deterministic layer drops accepted findings, then: confidence below 0.5 -> `escalate`; no blocking findings -> `pass` (advisories land in `PORT.md`); last allowed round -> `escalate`; blocking set neither shrank nor gained anything new since the previous round -> `escalate`; otherwise `fix`. `escalate` parks the stage in `waiting_human` with `accept` (the remaining blocking findings become accepted deviations) or `reject` (cancels the run).
- `fix:<t>` has `maxAttempts: 5`; a successful fix resets `build`, `test`, `critique`, `fix`, and `report` for the target, and attempt counters carry on. Each stage otherwise has `maxAttempts: 3`; a stage that returns a non-retryable failure (`build-error`, `test-failure`, `budget-exhausted`, `unsupported-source`) blocks at once.
- Budget: `budgetUsd` defaults to $30 and is capped at $100 by the schema; every worker call is capped as in 3.2; the run pauses when its total reaches the budget. Budget exhaustion inside a worker is reported as `budget-exhausted` and never retried with the same cap. There is no wall-clock cap and no top-up control.
- Cost: Agent SDK `total_cost_usd` (incrementally for resumed sessions). `packages/core/src/cost/prices.json` holds a price table for the Messages path.

### 3.4 Parallelism and lanes

LLM workers run with `concurrency.agents` (default 3). Lanes in `packages/harness/src/lanes.ts`, limits from `concurrency.lanes`: `xcodebuild` 1, `gradle` 1, `simulator` 1, `emulator` 1, `web` 2; unknown lanes default to 1. Targets without an adapter or with a missing toolchain are `skipped` with the reason.

## 4. WASM core

**Extraction criteria** (`packages/analyzer/src/candidacy.ts`, deterministic score, then the plan worker confirms or overrides with a rationale): in `auto` mode the core is enabled when the pure logic units marked `coreCandidate` total >= 150 LOC, or when at least one of them has >= 30 LOC and its name or description matches the "valuable" list (dates, scheduling, pricing, totals, tax, scoring, serialization, parsing, formatting, validation, currency, units, recurrence, budgets, shipping, inventory, matching, sorting, filtering, search, diff, merge). `always`/`never` override. The plan may disagree with the heuristic; the disagreement is logged with both rationales.

**ABI contract** (`docs/ABI.md`, v1): target `wasm32-unknown-unknown`, `panic = "abort"`, `lto`, `opt-level = "z"`, **zero imports** so one binary runs unchanged in WasmKit, Chicory, and browsers with no WASI shims; the Node host refuses a module with imports. Exports: `memory`, `mpf_abi_version() -> i32`, `mpf_alloc(len) -> ptr`, `mpf_free(ptr, len)`, `mpf_call(name_ptr, name_len, req_ptr, req_len) -> i64` (high 32 bits ptr, low 32 bits len of UTF-8 JSON), `mpf_manifest() -> i64` (JSON list of functions with input/output JSON Schemas). Envelope `{"ok":true,"value":...}` or `{"ok":false,"error":{"code","message"}}` with the codes `invalid_input`, `unknown_function`, `unimplemented`, `internal`. Determinism rule: no clock, RNG, locale, or I/O inside; `nowMs`, `timeZone`, `locale`, `seed` are explicit inputs. Crate template (`packages/wasm-core/src/template.ts`): `Cargo.toml` (`cdylib` + `rlib`, serde, serde_json), `src/lib.rs` (ABI glue), `src/api/*.rs` with one stub per planned function, `tests/vectors.rs`, `vectors/`.

**Host bindings**, generated from the manifest by templates in `packages/adapters/src/core/`, no LLM: Swift `MpfCore.swift` on WasmKit 0.4.0 via SwiftPM in the XcodeGen `project.yml` (raises the deployment target to iOS 18.0 and needs Xcode 26.3+); Kotlin `MpfCore.kt` on Chicory 1.7.5 (interpreter, minSdk raised to 28) with the wasm as an asset; web `mpf-core.ts` on `WebAssembly.instantiate`. Each target scaffold embeds the module, the binding, the vector files, and a parity test that the target's normal unit-test command runs (`writeCoreEmbed`).

**Golden-vector differential parity**: `vectors/<fn>.json` entries `{id, input, expected, provenance, note?}` asserted by five hosts: Rust native (`cargo test`), the Node host (in `core.build`), the web scaffold's vitest, XCTest through WasmKit on the simulator, JUnit on the JVM through Chicory (no emulator needed). Results keyed by function and vector id form the parity matrix on the dashboard's tests page.

**Fallback when no core**: logic is implemented natively per target by the generation worker; `PORT.md` records the plan's rationale.

**Other WASM uses**: tree-sitter grammars in the analyzer; the dashboard core page loads the produced `mpf_core.wasm` in the browser to run and tweak vectors. Rejected as unjustified: running orchestrator logic in WASM, WASM-sandboxing agents, wasm-bindgen/wasm-pack (the JSON ABI removes the need). Optional later: `wasm-opt`.

## 6. Critic (`packages/critic`)

- Independence: never sees worker transcripts or prompts; context is built from artifacts (AppSpec, BehaviorSpec, PortPlan, the latest test results per kind, build diagnostics, the generation worker's structured summary, screenshot paths, prior verdicts, the accepted-deviation set) plus read-only access to the workspace, the source, and the run directory; distinct system prompt; `models.critic` can differ from the generate model.
- Rubrics are constants in `src/rubrics.ts`: fidelity, idiomatic (one per target, web as the fallback), test adequacy, parity documentation, build health, privacy and safety. `rubricsFor(target)` assembles the system prompt.
- One backend: an Agent SDK worker (`runWorker` with role `critic`, Read/Grep/Glob and read-only Bash, `CriticOutput` as the structured output). The Messages path from the plan is not wired.
- Deterministic decision on top (`src/decide.ts`): findings get stable ids (hash of category, behaviorId, file, and the first 80 characters of the description); accepted ids and accepted deviation texts are dropped; then confidence < 0.5 -> `escalate`; no blocking -> `pass`; last allowed round -> `escalate`; blocking set unchanged since the previous round -> `escalate`; otherwise `fix`.
- Routing: `fixBrief(verdict)` lists blocking findings with file, line, behavior, suggested fix, and evidence, then advisories, for the fix worker. Stable ids enable the shrink check; the critic receives prior verdicts and the accepted deviations so they are not re-raised.

## 8. Doctor and setup

`mpf doctor` (`packages/harness/src/toolchain/`, each check returns status, effect, and a fix hint per package manager): `node` (>= 22.13), `git`, `pm` (pnpm or npm), `llm` (Claude access: `messages` with `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, or an `ant` profile; `agent-sdk` with a Claude Code login), `xcode` (macOS only: a full Xcode through `DEVELOPER_DIR` or `xcode-select`, an iOS simulator runtime, `xcodegen`), `java` (JDK 17-24 through `JAVA_HOME`, `/usr/libexec/java_home`, Homebrew `openjdk@21`/`openjdk@17`/`openjdk`), `android` (`ANDROID_HOME`/`ANDROID_SDK_ROOT`, then the usual SDK locations: `adb`, a platform, build-tools, `emulator`, a system image, an AVD), `gradle`, `rust` (`cargo` from PATH, `~/.cargo/bin`, or `<brew prefix>/opt/rustup/bin`, plus the `wasm32-unknown-unknown` target), `maestro`. The report derives `availableTargets` and `llmBackend`. There is no Playwright Chromium check.

`mpf setup [--yes] [--dry-run]`: lists what the doctor reports missing, asks before each install, never runs `sudo` without confirmation of that exact command, `--yes` for CI, `--dry-run` prints the plan.

**First-run notes for a macOS machine** (not product code; `mpf setup` does the equivalent):

```bash
sudo xcode-select -s /Applications/Xcode.app      # or set DEVELOPER_DIR
export JAVA_HOME=$(/usr/libexec/java_home -v 21)  # JDK 17-24; Gradle 8.14 fails on newer ones
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0" "emulator" "system-images;android-36;google_apis;arm64-v8a"
avdmanager create avd -n mpf-api36 -k "system-images;android-36;google_apis;arm64-v8a"
brew install rustup && rustup default stable && rustup target add wasm32-unknown-unknown
brew install xcodegen
brew trust mobile-dev-inc/tap && brew install --formula mobile-dev-inc/tap/maestro   # `brew install maestro` is an unrelated cask
pnpm --filter @mpf/analyzer exec playwright install chromium
nvm install 24   # node:sqlite is unflagged from 22.13
```

## 10. Verifying the factory itself

- Unit: schema round-trips and JSON Schema export; state machine transitions (table-driven plus `fast-check` properties); the event reducer shared by the server tests and the dashboard; Maestro and web flow compilation; the permission policy; cost accounting.
- LLM paths without credentials: stages take an `AgentFn` so tests pass fakes; `AgentRecorder` appends worker events as JSONL (no replayer yet); critic decision logic on synthetic verdicts.
- Harness with fixtures: adapter `detect()` over the in-house fixtures and the synced public matrix; each target scaffold builds green (`scripts/spike-target-scaffold.ts`, which also launches, runs a flow with `--e2e`, and checks shared-core parity with `--core`); log parsers for xcodebuild, gradle, JUnit, and Maestro on captured output.
- End to end without an LLM: `pnpm mpf port fixtures/inhouse/web-vanilla-counter --to web,android --fake --yes` runs the fake pipeline through the real daemon, SSE stream, and reducer.
- CI (`.github/workflows/ci.yml`): `checks` on ubuntu and macos-15 (lint, format check, typecheck, tests with Rust and Chromium installed, the fake pipeline, the dashboard build, the bundled CLI's `--help` and `doctor`); `web-scaffolds` (vanilla, react, vue, svelte with a Playwright flow); `mobile-fixtures` (the iOS fixtures through XcodeGen and `xcodebuild test` on a simulator on macOS; the Android fixture through `assembleDebug testDebugUnitTest` on ubuntu); `fixture-matrix` (sync the public repos and run the detection test). Real-LLM and device-driven port runs are not in CI.
- Without the daemon: `scripts/run-control.ts <runId> resume|rerun <stageId>|answer <stageId> <choice> [note]|status`, or `new <source> --to ios,android [--until <stage>] [--budget <usd>] [--yes]`, drives a run in-process on the current code; `scripts/compile-flows.ts <runId> <target>` recompiles a target's flows from the stored BehaviorSpec without a device.

## 11. Project scaffolding

- `.gitignore`: `node_modules/`, `dist/`, `dist-release/`, `.nuxt/`, `.output/`, `.turbo/`, `coverage/`, `*.tsbuildinfo`, `*.log`, `.env*`, `fixtures/.cache/`, `**/DerivedData/`, `**/.gradle/`, `**/build/`, Rust `**/target/` with `!packages/adapters/src/target/` re-included (ESLint honors `.gitignore`), `templates/**/*.xcodeproj` and `fixtures/inhouse/**/*.xcodeproj` (XcodeGen output), `**/local.properties`, editor and OS files.
- `CLAUDE.md`: what the product is; commands; package map and dependency direction; invariants (orchestrator deterministic; schemas zod-first in `core`; adapters are the only home for platform knowledge; no hardcoded machine paths; no user-specific defaults; every LLM call goes through `@mpf/llm`; budgets always enforced; run data under `~/.mpf`; events are the source of truth); how to add an adapter (`docs/ADAPTERS.md`); style; gotchas that grew as spikes landed; status per milestone.
- Root scripts: `dev` (turbo: server + dashboard), `build`, `test`, `test:watch`, `typecheck`, `lint`, `format`, `format:check`, `mpf` (`tsx apps/cli/src/main.ts`), `doctor`, `fixtures:sync`. Release is `pnpm tsx scripts/release.ts [--publish]`. `apps/cli/package.json`: name `multiplat-factory`, `bin: { mpf }`, `engines.node >= 22.13`, `build: tsup && node scripts/bundle-dashboard.mjs`.

### Critical files

- `packages/core/src/schemas/index.ts` (all zod schemas + JSON Schema export; everything types against it)
- `packages/adapters/src/types.ts` (`SourceAdapter` / `TargetAdapter` interfaces; the generality extension point) with `src/registry.ts` and `src/target/registry.ts`
- `packages/orchestrator/src/graph.ts`, `machine.ts`, `runner.ts` (stage DAG, deterministic state machine, scheduler)
- `packages/llm/src/agent.ts` and `packages/analyzer/src/worker.ts` (Agent SDK spawn: permissions, budgets, structured results, resume, session ledger)
- `docs/ABI.md` (WASM core contract implemented by the Rust template and the three host bindings)

### Assumptions that were verified at implementation time

Agent SDK option names (listed under "Verified facts"); streaming-input steering is not used, instructions arrive at worker start; WasmKit 0.4.0 runs on the simulator with Swift 6.3 tools and adds about three minutes to the first build; Maestro's iOS driver works on iOS 26 simulators once flows avoid external URL opens; `tree-sitter-wasm` ships java and objc grammars; the todomvc license is still marked "check before vendoring" in the manifest; the `@multiplat` npm scope is unverified until the first publish.
